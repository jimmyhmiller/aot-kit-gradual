# B13 pinned-corpus string surface

The executable inventory in `benchmarks/v8-v7/capabilities.json`, regenerated by
`tools/v8-inventory.mjs`, is the source of truth for string literals and call spellings in all
eight pinned programs. B13 implements the primitive-string and conversion operations it exposes:

- UTF-16 literals, length, content equality, concatenation, and lexicographic relations;
- `charAt`, `charCodeAt`, `substring`, `substr`, `slice`, plain-string `split`, and `indexOf`;
- corpus-ASCII `toLowerCase`/`toUpperCase`, `String.fromCharCode`, `String(value)`, integer
  `toString(radix)`, `parseInt`, and `isNaN`.

The corpus audit also records forms whose owning capability is deliberately later in the roadmap:

- RegExp arguments to `split`, plus `match`, `replace`, `exec`, and `test`, belong to B21.
- `new String(value)` is an object wrapper and belongs to the dynamic object/builtin closure work;
  its underlying primitive conversion and every string method it consumes are present here.
- User-defined and general object `toString` calls require dynamic receiver dispatch and are not
  represented as primitive-string operations.

The pinned case-conversion inputs and class tables are ASCII. B13 therefore implements the exact
corpus behavior without claiming locale-sensitive or full Unicode case mapping beyond this suite.
